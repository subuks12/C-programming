(1) The `time` command reports elapsed wall-clock time (`real`), CPU time spent executing the program (`user`), and CPU time spent in the operating system (`sys`). In my run of the search for `help` in `data/warnpeace.txt`, the output was `real 0m0.022s`, `user 0m0.019s`, and `sys 0m0.002s`. The search found 207 instances. These timings vary with system load; stdout was redirected during this timing run to avoid counting terminal rendering of the instance lines.

(2) I did not encounter data races. The input file is mapped read-only, and each worker scans a disjoint, line-aligned byte range while writing only to its own count and instance array. The main thread waits for every worker with `pthread_join` before combining partial results in file order, so workers never modify shared result data.

(3) The OpenMP version uses a `parallel for` directive to distribute file chunks among threads, and the runtime manages thread creation, scheduling, and synchronization. The pthread version explicitly creates and joins threads and passes each one its own arguments. Both versions use a read-only file mapping and separate partial results, then combine those results after workers finish.
